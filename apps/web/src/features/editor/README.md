## The model, in short

- **Stops.** A voice's stops are its beats, then one end slot when the bar is not full; an empty voice has only the end slot. The cursor walks stops bar after bar, in its own track and voice (`EditCursor.at.beat` indexes them).
- **The cursor holds ids** (`track`, `masterBar`, `beat`), so an edit, undo or redo leaves it on its beat. `reconcile` runs on each edit: a removed beat moves it to the stop at the old index, a removed bar to the first stop of the bar at the old index, a removed track to the current track; the string is clamped; a range end whose beat is gone widens to its bar, and one whose bar or track is gone clears the range. Undo restores a beat with its id, but the cursor has already moved to a beat that exists and stays there.
- **A click** resolves through `locate`: a note anchor gives its note, string and beat (a grace note maps to its parent beat); a beat anchor gives the beat, with the string read from the tab line nearest the click (`stringAt`: `clamp(round((y - top) / spacing) + 1, 1, n)` on the track's tab staff in that system, `n` the tuning length), or the cursor's string on a standard staff; a gap in a track's bar gives the nearest beat by x, or the end slot past the last one; the clef area gives the staff's first stop; a margin or gap between systems gives the nearest column's bar in the current track. Everything is in layout space, so paged, continuous and split systems share one path.
- **Ranges** compare `(bar index, tick in bar)` pairs, never absolute ticks, so pickups and over-full bars need no case. A `beats` range covers every voice of the tracks between its ends, from the earlier onset to the end of the later beat; a `bars` range takes whole master bars. A `RangeEnd` cannot name an end slot, so a cursor on one takes a neighbouring beat: as the earlier end the first beat of the following bar, as the later end the last beat of its own bar, the whole bar only where there is none. Each write goes through `rangePatch`, which keeps the transport's `bars` and `barsAnchor` in step.
- **`editTarget`** is what a command acts on: the range's beats, else the picked notes, else the note on the cursor's beat and string, else the cursor's beat, else nothing.
- **Mouse**: a click places the cursor, picks the note under it and, in the app, seeks a stopped playhead to it; Shift+click extends a beat range from the cursor; Cmd/Ctrl+click toggles a note in the picked set; a drag makes a range (previewed, restored on cancel); a press in a column's own area, above the staves where the bar number sits, takes whole bars.
- **Keyboard** (edit mode only, `context: 'editing'`): arrows move by stop and string, Home and End by bar, Ctrl/Cmd with them by bar and score, PageUp and PageDown by system (a continuous layout's segment), Shift extends a beat range (up and down by track), Ctrl/Cmd+Shift extends by bar, Escape clears the range and picked notes. A plain move clears both. The full list is in [keyboard-shortcuts.md](../../../../../docs/reference/keyboard-shortcuts.md).
- **Note entry** (edit mode, fretted tracks): a digit sets the fret on the cursor's string and the cursor stays put, so more digits on other strings make a chord; → advances (to the end slot of an unfilled bar, to the next bar from a full one, and past a full last bar it appends a bar as its own undo step). At the end slot a digit inserts a beat of the current rhythm; on a beat, overwrite mode replaces the fret and insert mode inserts a beat before it. A digit that can start a two-digit fret waits 500 ms (`TWO_DIGIT_MS`); any other key, a click or a cursor move commits it, Escape cancels it. The duration, dot, triplet, rest, tie, Enter, delete and voice keys are in the shortcut table. Every entry is one `chain` command, one undo step. A bar is never over-filled: the entry is refused with the room left ("Bar 3 has an eighth left: a quarter does not fit"), shown in the status line. Insert or overwrite is a session setting, switched from the palette (on Windows the Insert key inserts a bar, see below). Drum and keyboard tracks are #221.
- **Demo**: `/dev/score?edit=1` (see the score demo's README for how to serve it; it takes the same `fixture`, `mode` and `notation` parameters) mounts `demo/edit-demo.tsx`, the cursor and range over a fixture or the long score with no app around it.

## Bars and the master-bar dialog (WP-083)

- **Target** (`bar-edit.ts`, `barTarget`): the bars of the range, else the cursor's bar. Every bar command is in the editing context.
- **Bars** (`bar-commands.ts`, `bar-actions.ts`): insert before (⌘+ or ⇧⌘+, Insert on Windows) or after (palette) puts the cursor in the new bar; delete bars (⌘⌫, Ctrl+Delete) is one `chain` of `removeBar` from the highest index down, refused up front when it would take every bar. `[` and `]` toggle the repeat start on the first bar and the repeat end on the last, shadowing the tempo steps while editing.
- **Master-bar dialog** (`master-bar-dialog.tsx`, state in `master-bar-form.ts`): ⌘T (palette aliases for key, tempo, repeats, directions (D) and section start in that section). Repeat start, tempo, section, segno and coda go on the range's first bar; repeat end, jump and Fine on its last; endings, time and key on every bar, the last two continuing until the next change by default. Only touched fields are written, a field whose bars differ shows "Mixed", and a whole apply is one `setMasterBars` (one undo step). A smaller time signature that no longer holds a bar's notes is refused with the bars named.

## Tracks and New song (WP-083)

- **Track dialog** (`track-dialog.tsx`, state in `track-form.ts`): name, short name (follows the name until edited), colour, kind (chosen when adding, read-only afterwards), string count, tuning from `STANDARD_TUNINGS` or custom (string 1 listed first, flipped once against `Track.tuning`), capo and GM program. A tuning change keeps the frets; dropping strings that still hold notes is refused up front, naming the strings and bars. Editing is one `setTrackProperties` with only what changed; adding is one `addTrack` at the end.
- **Commands** (`track-commands.ts`): `track.properties` (F6), `track.add` (⌥⌘N) and `track.addWindows` (Ctrl+Shift+Insert), `track.remove` and `track.moveUp`/`track.moveDown` with no keys. `track-edit.ts` holds the actions the sidebar menu shares.
- **Dialog host** (`editor-dialogs.tsx`, `dialogs.ts`): `<EditorDialogs />` is mounted once in the app; the open dialog lives in a store keyed by the services (`dialogsOf`).
- **New song** (`new-song.ts`): `startNewSong` opens `newDocument(createEmptyScore())` and turns edit mode on, after `whenSaved` (`app/when-saved.ts`: Save, Don't save, Cancel) when the document is modified. `whenSaved` and its dialog live in `app/` because Open, Close and the library's open entries share them (WP-061).
- Refusals read through the shared `describeRefusal` (`refusal.ts`).

## Effects (WP-082)

Effect keys are Guitar Pro 8's, bound in the `editing` context by `effect-commands.ts` (the table is in `docs/reference/keyboard-shortcuts.md`). Every one goes through `runEffect`, which flushes a pending digit, resolves the target, and applies the plan as one undo step through `commitEdit` with the cursor left alone.

- `effects.ts`: `planEffect(input, action, mode)` is pure. `EffectAction` names an effect with its whole value (a bend preset is one action). `mode` is `toggle` (Guitar Pro's rule: remove when every target has exactly that value, else set on those that lack it), `set` (a picker's choice) or `remove` (a picker's Remove, whatever the value). Only the nodes that change are written; when none do the plan is `{ nothing: true }`. The exclusive groups (shift and legato slides, accent and heavy, slight and wide vibrato, tapping, slap and pop, the fades, brush and arpeggio) are kept by the planner, never by the model. A node that cannot take an effect (a drum note for a fretted effect, a shift slide with nothing to slide to, a prebend on a tied note) is marked `unavailable`: setting skips it and says so in the plan's `notice` (shown on the status line), refusing only when no node can, and removing never skips, so an effect already there always comes off.
- `effectCommand(label, edits)` is the one place an effect becomes a model command, so a change to the model's batch commands touches one function.
- `effect-targets.ts`: the notes and beats an effect reaches, from `editTarget`. A note effect on a beat target reaches every note of the beat (D7); a beat effect reaches the beats of the notes picked; rests and empty beats drop out.
- `next-on-string.ts`: the next note on a string within a bar reach. H sets `hammerPull` on the target within the tie reach (D2), a shift or legato slide needs one in this bar or the next. A tied note is held, not struck, so it counts as nothing to connect to. A grace note slides or hammers into the main note of its beat on its string, as layout draws it.
- `effect-state.ts`: `effectState` is `on`, `off`, `mixed` or `unavailable`, for a button's `aria-pressed`.
- `bend-presets.ts` and `whammy-presets.ts`: the curves, each one gpif curve so a gp export keeps it. A prebend on a tied note is refused, since gpif reads the curve of a tied note as a hold or a release.

- `effects-panel.tsx`: the right panel's Effects view (`editor.toggleEffectsPanel`, palette only). Every effect is a button whose `aria-pressed` is `effectState` (`true`, `false` or `"mixed"`); a press runs the registry command its key runs (`useCommand`), so panel, keys and palette cannot drift. Buttons do not take focus on click. Disabled outside edit mode, on an empty selection and where the effect is unavailable. The app mounts it in `RightPanel`.
- `effect-pickers.tsx`, `grace-dialog.tsx`, `grace-form.ts`: the effects that take a choice are modal dialogs hosted by `EditorDialogs` (kinds `effectPicker` and `grace` in `dialogs.ts`), never popovers: the dispatcher lets keys through a non-modal popover, and a key would then edit the score under it. `picker-commands.ts` binds B (bend), ⇧S (slide kinds), ⌥Y (harmonic), ⌥V (whammy), G and ⌥G (grace). `effect-dialogs.ts` opens them and refuses first (`pickerBlocker`, `graceBlocker`): a picker never opens on an empty or refused target, the status line says why. A choice goes through `applyEffect(services, action, mode)`, which returns `{ applied }`, `{ refused }` or `{ nothing }`: a picker applies in `set` mode (a slide in `toggle`) and closes, `Remove` uses `remove`, and a refusal keeps the dialog open with the sentence in an alert. Each application is one undo step. The grace form (`planGrace`) writes one grace beat per target beat with a grace note on every targeted string; the dialog owns `hammerPull` on the main notes of the strings it puts a grace note on: Apply writes it to match the transition (on for a hammer-on, off otherwise, only where it changes) and Remove clears it, so a grace hammer never leaves an arc from the previous note. The dialog opens on the transition read from the beat that holds the grace notes. Alt+G opens on the existing grace note's own placement when there is one. Focus returns to the panel button that opened a dialog only when the keyboard did (a click never took focus, so it must not be given it), else to where it was.
- Also pickers: trill (N: removes when every note has one, else an interval in whole frets above each note, two by default or the one the target already trills by, and a speed; a note the interval would take off the neck is skipped and reported), tremolo speed (8, 16, 32) and dynamics; the last two have no key. The harmonic node and the trill interval open on the value the whole target shares. `panel-state.ts` reads every control from one resolved target (`resolveEffect`, `effectState` and the blockers take it), which cost about 250 ms on a select-all of `largeScore(8, 300)` before and about 65 ms after. `EditStatusLine` shows an Effects button when it is given `ui`. A refusal in a dialog reads only in the dialog (`quiet`).

## Clipboard (WP-084)

- **The clip** (`clipboard-format.ts`): a zod schema, version 1. A `beats` or `bars` clip holds, per track in score order, the bars the range touched with their time signatures and, per bar, the voices with their beats and each voice's start in ticks. A bars clip keeps all four voices. Ids stay in it so it validates and are never reused: a paste gives every beat, note and grace note a fresh id.
- **System clipboard**: `text/plain` carrying the line `Reprise clipboard 1`, then the clip as one line of JSON; text that does not parse (another version, foreign, over 8 MB) is not a clip. Copy, cut and paste go through the DOM `copy`, `cut` and `paste` events (`clipboard-events.ts`), which the keyboard raises in the browser and the native Edit menu's roles raise in Electron, so no clipboard permission or IPC is needed. Commands `editor.copy`, `editor.cut` and `editor.paste` are `native`: the dispatcher leaves ⌘C, ⌘X and ⌘V to the browser. The handler stands aside, leaving the event alone, in a text field, under a modal, outside edit mode and (copy, cut) while text is selected. The palette's Copy and Cut raise the event themselves with `execCommand`, falling back to the internal clipboard when none arrives; its Paste, Paste as insert and Paste over read the internal clipboard only (`clipboard-store.ts`), which survives a document switch.
- **Copy** (`clip.ts`): the range's beats or bars across its visible tracks, else the beat under the cursor. A tie that reaches back before the clip is cleared. **Cut** is one `replaceBeats`: a bars cut empties the bars and keeps them, a beats cut puts rests of the same total length where the beats were (a rest like each beat when no plain rests fill a tuplet), so what follows keeps its time against the other voices and tracks.
- **Paste** (`paste.ts`, pure): one `chain` of `insertBar` steps (bars appended past the end, or the new bars of an insert-paste) and one `replaceBeats`, so one undo step. The clip's tracks go onto the visible tracks from the cursor's (or the range's first) track down, same kind only. ⌘V follows the status line's insert or overwrite mode. Overwrite replaces the beats the clip's length covers (padding the difference with rests so later beats keep their time) and never edits a bar's properties; it refuses a bar that would overflow, naming the bar and the room left. A beats clip starts at the cursor's stop and refuses a start that is not where a beat begins. A beats clip over a barline pastes only at the position in its bar it was copied from (`Clip.start`), so its bars stay contiguous around the target's own beats; whole-bar clips have no such limit. A track with nothing in the span is left as it is. A clip of one voice pastes into the cursor's voice. A fretted clip with another string count is re-fingered by pitch (`refinger.ts`), frets counting from each track's capo as `midiNote` does: the string tuned to the same open pitch first, then the lowest fret. A trill moves by the same number of frets and is dropped off the neck, a natural harmonic that moved is flagged, and the notice names every neck, the notes left out and the trills dropped. The cursor lands on the first pasted beat or bar and the pasted span becomes the range.
- The status line's message has a tone: a refusal reads as an error, a notice (Copied, Pasted, Re-fingered) does not.

## Chord names, beat text and lyrics (WP-085)

`A` opens a chord name, `T` beat text and `⌥L` a lyric line, in an inline field (`word-field.tsx`) placed over the score at the beat it edits (`wordFieldRect` in `geometry.ts`): on the baseline of the word the beat already has in that lane, else where its lane would go. No lane is reserved when the field opens, so the layout grows only when a word is committed (in continuous mode a track's first chord, text or lyric line changes the shared height and re-lays the whole score once, #229).

- **State.** The session lives in the entry store (`word`, `lastLyricLine`); `word-session.ts` holds the operations (`openWord`, `commitWord`, `stepWord`, `switchLyricLine`, `finishWord`) and the field only maps keys to them. The field closes when edit mode ends or its beat disappears.
- **Planning.** `planWord` (`words.ts`) is pure: it returns one `chain` labelled "Chord name", "Text" or "Lyrics". A rename keeps the chord's diagram; emptying the name removes the chord and its diagram with the notice "Chord diagram removed". A lyric write pads and trims the beat's lines, and the first lyric edit on a track clears its raw `Track.lyrics` block in the same chain, so a deleted lyric cannot come back from it.
- **Moving.** `word-nav.ts`: chords and text go to any beat of the cursor's voice, rests included; lyrics go to played beats of voice 1. Moving also moves the edit cursor.
- **Undo.** Each committed beat is one undo step (`commitEdit` with `moveCursor: false`); an unchanged word writes nothing.
- **Keys.** The field handles Tab, ⇧Tab, Enter, Escape, Space, `-`, ⇧Space, ↑, ↓ and Backspace itself and stops them at the field; the dispatcher already leaves bare keys to a text field, so no editor shortcut sees the rest (#226). A click on the History panel blurs the field first, so the word is committed (a step, and the redo stack cleared) before the jump runs; the window losing focus does not commit. Suggestions are the song's own chord names, most frequent first (`chord-suggestions.ts`); there is no chord builder and no diagram editor in v1.

## Undo (WP-084)

- **Labels** (`history-labels.ts`): `historyLabel(name)` turns the name the model records (`insertBar`, a chain's `pasteBars`, an effect's "palm mute") into what the user reads ("Insert bar", "Paste", "Palm mute"). One map; a name already written as text is kept and capitalised, any other id becomes sentence case. `app.tsx` passes it to `installHistoryMenu` as the `display` mapper, and `app/edit-commands.ts` builds the palette's "Undo Insert bar" and "Redo Paste" from it (a getter, read when the palette draws).
- **History panel** (`history-panel.tsx`, the right panel's `history` view; the command `editor.showHistory` toggles it): the start row ("Opened", or "New song" for a document made in the app), the applied edits oldest first with the newest marked `aria-current="step"`, then the edits Redo would bring back, dimmed. A grouped edit (a paste, a typed entry, a range effect) is one row. A click, Enter or Space on a row jumps there by repeated `undo()` or `redo()` of the document store, with no model API of its own; the list is one tab stop (arrows, Home and End move). The buttons on top carry the labels ("Undo Insert bar").
- **The cursor after an undo or a redo** (`undo-landing.ts`, pure, called by `installEditor` when `lastStep` is `'undo'` or `'redo'` and edit mode is on; in play mode the hidden cursor and the current track stay put): read from the replayed `lastChange`. Content patches (a beat or a note) rank above structural ones (`insertBar` adds a bar to every track): the first content patch under the cursor's track, else under any visible track, else the first structural one, picks the track; on it the earliest position in the score wins (a paste patches in no order). A beat path gives that beat (the restored beat after an undone delete; the stop that took its place after a redone one), a note path also its string (a removed note's own, read from the opposite patches), a bar or voice path that bar's first stop, a master-bar path that bar's first stop in the cursor's track. A patch that removes a bar, voice or master bar, or changes a track's own properties, moves nothing. When no patch says, `reconcile` still keeps the cursor on a stop that exists, and it always settles the range and picks.

## Transposition and string moves (WP-085)

- **`transpose.ts`** (`planTranspose`, pure): the plan for the Transpose dialog and the semitone keys. The scope is the selection (`editTarget`: the range's beats, else the picked notes, else the cursor's note or beat), the current track (every voice) or the song (every track, hidden ones included); drum tracks are left out and the notice says so. Notes stay on their strings, frets count from the capo, tie chains follow their origin, and the capo never moves (decision D7). Before building anything it runs the model's `transpose()` over every note the scope reaches and refuses with a sentence naming the track, bar and string ("Track 2, bar 14, string 6: fret 0 cannot go down 2 semitones without falling below the open string", "below the capo", "past fret 24", "leaving the MIDI range"); the model's own `off-fretboard` refusal stays as the backstop. The plan is `chain('Transpose', [transposeSelection, setBeatEffects?, setMasterBars?])`, one undo step. Warnings the model will raise (a trill that fell off, a natural harmonic that left its node) are counted in the same pass and read as a notice.
- **`chord-names.ts`**: `transposeChordName` moves the root and the slash bass and spells them with `spell()` for the key in force at that bar after the edit, keeping the quality as typed; a name that is not a chord (`N.C.`, `Riff`) stays and is counted, and a move by whole octaves leaves names alone. `shiftDiagram` moves a movable shape (no open string, staying on frets 1 to `fretCount`) and `undefined` otherwise, when the diagram is removed with a notice (decision D8). `transposeKey` takes the spelling with the fewest accidentals, keeps the mode, and at the tritone keeps the original's side. Chord names move only when the scope names beats, never for notes picked on their own.
- **The key signature** moves only when the scope covers every non-drum track (the song, or the current track in a score with one pitched track), because the key belongs to the master bar all tracks share (decision D8).
- **`string-shift.ts`** (`planShift`): Alt+Up and Alt+Down, `shiftStrings` on the fretted tracks of the target, with the model's refusals found first and worded with the bar ("There is no string above string 1", "Fret 2 on string 3 would be fret −2 on string 2", "String 2 already has a note in bar 4"). A tie moves as a whole (the followers go with the origin; a follower picked without its origin refuses), and a picked grace note refuses with "Grace notes move with their beat", as it does for transposition. Every refusal names the bar. When the target is the note under the cursor itself, the plan carries that note's new string so the key repeats.
- **`transpose-commands.ts`**: `editor.transposeDialog` (palette only), `editor.transposeUp` and `editor.transposeDown` (⌥⇧↑ and ⌥⇧↓: the selected notes only, no chord names or key, decision D5) and `editor.moveNoteUp` and `editor.moveNoteDown` (⌥↑ and ⌥↓; `editor.stringUp` and `editor.stringDown` are the cursor's own keys). **`transpose-dialog.tsx`** with its state in **`transpose-form.ts`**: −24 to +24 semitones (opens on the last amount used, else +1), the scope (Selection is disabled with no target and is the default only with a range or picked notes), the two options, and a refusal in the dialog's alert with the dialog kept open. History labels: "Transpose" and "Move to next string".

## What it can rely on

- `editing` (`state/editing.ts`): the edit-mode flag, `editing`, `setEditing` and `toggle`. It is off
  at the start of every document. Read it to switch clicks from seeking to editing.
- `selection` (`state/selection.ts`) for the current track, the edit cursor, the range and the picked notes, written only through `setEdit`.
- `document.apply(command)` for every edit, so each is one undo step through the history.
- `audio.previewTrack`, and `audio.previewNote(trackId, { string, fret } | { pitch }, { velocity?, seconds? })` (#204), which throws `RangeError` on bad input, so an entry calls it last, after the edit. An entry's preview takes its velocity from the note's dynamic (`DYNAMICS_VELOCITY`) and its seconds from the beat's written length at the tempo in force (`preview.ts`).

Entry state that no other feature reads (duration, insert versus overwrite, the waiting digit) lives in `entry-store.ts`; the voice is the edit cursor's, which lives in the selection store.
